= consent-aware-web — Quick Start for Platform Maintainers
:toc:
:toclevels: 2

== Overview

This guide covers packaging, deploying, and maintaining consent-aware-web for
distribution on your platform.

== Runtime Dependencies

None. The deliverables are documents and a JSON Schema; there is nothing to
install or run in production.

Build-time only: `just`, a draft renderer (xml2rfc or the author-tools.ietf.org
API — see STATE.a2ml blockers), a JSON Schema validator, and `lychee` for link
checking. The reference implementations need Bun (tier 1) or Deno (tier 2).

== Build from Source

[source,bash]
----
git clone https://github.com/metadatastician/consent-aware-web.git
cd consent-aware-web
just build-drafts
----

Output: `build/drafts/` — rendered `.txt` and `.html` for each Internet-Draft (gitignored).

== Packaging

=== Guix

[source,bash]
----
guix build -f guix.scm
----

=== Container (Stapeln)

[source,bash]
----
just stapeln-export    # Generates Containerfile
podman build -t consent-aware-web .
----

=== Manual Package

[source,bash]
----
just install --prefix=/usr/local
----

Files installed:

[cols="1,2"]
|===
| Path | Contents

| `$PREFIX/bin/`
| Executables

| `$PREFIX/share/consent-aware-web/`
| Data files, assets

| `$PREFIX/share/doc/consent-aware-web/`
| Documentation

| `$PREFIX/share/applications/`
| .desktop file (Linux, if GUI)

| `$PREFIX/share/man/man1/`
| Man pages
|===

NOTE: This suite installs nothing. The table above is retained from the RSR
template for repositories that ship an executable; for this one, packaging means
distributing the rendered Internet-Drafts and the JSON Schema.

== Configuration

None. There is no installed program and therefore no configuration file.

The only file a *consumer* configures is their own `/.well-known/aibdp.json`,
published on their origin. `docs/example-aibdp.json` is the starting point and
`schemas/aibdp-schema-v0.2.json` is what it must validate against.

== Health Checks

There is no daemon to health-check. What can go wrong here is that a *claim*
stops matching the tree, so the checks are assertions about the repository:

[source,bash]
----
just test                              # drafts valid, manifests valid, links live, drafts unexpired
bash scripts/check-root-shape.sh .     # root contents match the allowlist
bash scripts/check-no-md-in-docs.sh .  # no .md under docs/
----

To check a *deployment* of the protocol rather than this repository, run the
four-request enforcement check in
`examples/reference-implementations/README.adoc`. A server that reports
"enforcement: ENABLED" has not demonstrated anything; only a 430 has.

== Updating

[source,bash]
----
git pull
just build-drafts     # re-render drafts/*.xml
just test             # confirm the claims still hold
----
