== 2. Why E and not higher

*D* requires RSR compliance, per-capability tests, and documented scope. Three of
those are now met — but D also requires the capability itself to be coherent, and
for a *specification* the capability is "a third party can implement this and
interoperate". Nothing here demonstrates that. There is one implementation, written
by the same author as the specification, tested against a manifest written by the
same author. That is self-consistency, not validation.

*C* additionally requires dogfooding with *no known failures over an evidence
window*. This repository has been dogfooding its own protocol for hours, not a
window. It also requires deep per-file annotation, which is not present.

The honest reading is that the *repository* is in reasonable shape and the
*specification* is pre-alpha. CRG grades the weakest in-scope component, so E.

== 4. What would move the grade

To *D* overall: a committed negative corpus and unit tests for the middleware's
policy-resolution functions. Both are cheap.

To *C*: an evidence window of dogfooding with no known failures, plus per-file and
per-directory annotation.

To *B*: the thing that actually matters — a conformance suite plus a second,
independent implementation that passes it. Until a specification has been
implemented by someone who did not write it, its readiness is unmeasured rather
than high.
