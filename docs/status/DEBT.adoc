== The five that matter

. *Nobody outside this repository has implemented AIBDP.* One implementation,
  written by the specification's author, tested against a manifest written by the
  same author, is self-consistency rather than validation. This is why
  `READINESS.adoc` grades E and not D — and no amount of internal work moves it.
. *AIBDP is a competing vocabulary until its AIPREF mapping lands.* `vocab-06`
  §6.6 permits alternative serializations only where the alternative defines the
  mapping in both directions. That mapping now exists in the draft — but it is
  untested against the working group, and §4.3's subset-not-superset rule may yet
  force some AIBDP purposes to be re-expressed or dropped.
+
(*Resolved 2026-08-07, previously item 2:* policy resolution order and exception
direction are now normative — exceptions narrow and MUST NOT grant what the
enclosing policy refuses; cross-source conflicts defer to `vocab-06` §5.1.)
. *41 KB of manifest scenarios that no gate can validate.* They live as prose
  inside `examples/manifest-scenarios/README.md`; there are no `.json` files. This
  is precisely how the demo manifest came to declare `scope: ["/article.html"]`
  against a server serving `/article` — an example nothing checks will drift, and
  the middleware fails open, so it drifts silently.
. *`draft-structure` cannot check rendering.* `xml2rfc` is Python-only and the
  estate language policy denies Python. The gate checks what it can and says so,
  which is honest but not sufficient — a draft can be structurally valid and still
  fail at the datatracker.
. *The estate's Bun ruling was recorded but not in force, in three places —
  one now fixed at source.*
  `LANGUAGE-POLICY.adoc §1` makes Bun tier 1, yet:
+
--
* `governance-reusable.yml`, called estate-wide, fails any repository carrying a
  Bun lockfile *and* any `package.json` with runtime dependencies — which is
  Bun's own model, so adopting tier 1 was impossible rather than awkward.
  **Open:** `hyperpolymath/standards#592`.
* The four AI instruction files in the template tell agents to migrate Bun *to*
  Deno, and TypeScript to a language nobody uses. They propagate to every mint.
  **Open:** `hyperpolymath/rsr-template-repo#25`.
* A workflow using the Bun setup action was rejected before any job ran —
  `startup_failure`, zero jobs, no log. **FIXED 2026-08-07**, and the
  correction to the diagnosis is the more useful part. There were *two*
  independent blockers, either sufficient alone:
+
** *Allowlist* — permitted `denoland/*` but not `oven-sh/*`. `oven-sh` is not a
   GitHub-verified creator, so `verified_allowed: true` did not cover it.
   `oven-sh/*` added (19 → 20 patterns, nothing removed).
** *Lockfile* — removing only the `oven-sh/setup-bun@v2.2.0` entry from
   `actions.lock`'s `dependencies:` section, allowlist fixed and everything else
   identical, reproduced `startup_failure`.
+
Proven to run afterwards. **Method note worth keeping:** the API accepting the
allowlist change, and reading the pattern back at both org and repo level, was
*not* evidence a workflow would start. Only running one was. Two variables had
changed between the failing and passing attempts; attributing to the first
without isolating would have shipped a wrong cause into a PR body, this
register, and a memory file — it very nearly did.
--
+
Two of the three remain worked around here rather than fixed — a
dependency-free validator, and corrected rule files carried in this repository
only. They are fixed at source only when those PRs land.

== Debt introduced by this session

Recorded separately because it would otherwise be invisible.

* `docs/faq.adoc` and `docs/server-configurations.adoc` are pandoc output. They
  validate clean and were spot-checked, but neither has been read end to end.
* `docs/technical.adoc` and `docs/start-here.adoc` were *reconstructed* — their
  sources had lost all markdown markup. Prose was diffed against the originals to
  prove markup-only change, but the structure (which lines are headings, which are
  list items, where code fences belong) is my reading of unmarked text, not the
  author's.
* `draft-jewell-aibdp-00.xml` was migrated RFC-XML v2 → v3 by script. Verified
  lossless (71 attributes → 71 elements, prose byte-identical), but it is a
  machine transformation of a normative document and deserves a human read.
* `docs/directory-structure.md` was dropped and not replaced.

== Not debt

Listed so they are not repeatedly rediscovered and refiled.

* *`draft-expiry` will fail on 2027-02-08.* That is the gate working. The response
  is a revision, not an exemption.
* *`capabilities = []` in `rsr-profile.a2ml`.* This is the honest declaration for a
  specification suite, not an unfilled token. Declaring capabilities that do not
  exist is what the RSR oracle punishes.
* *Proof tier T5.* There is no ABI, no cryptography and no concurrency. The
  reference implementation is illustrative, not normative — proving it correct
  would prove the wrong artefact.
* *Four of six architecture layers undrafted.* `README.adoc` marks them "not
  drafted" and no milestone depends on them. Direction, not commitment.
